# ParkSense — product documentation

Strategy documents for turning ParkSense from a working app into a released
product. Produced with the founder skill pack from
[emotixco/claude-skills-founder](https://github.com/emotixco/claude-skills-founder),
installed in this repo at `.claude/commands/founder/`.

Read in order:

1. **[LAUNCH-READINESS.md](./LAUNCH-READINESS.md)** — a review of the app as it
   stands, and the seven blockers between here and taking money.
2. **[PRICING.md](./PRICING.md)** — what to charge, why the scan itself is worth
   nothing, and the four gates that must pass before a paywall exists.
3. **[GO-TO-MARKET.md](./GO-TO-MARKET.md)** — how the release happens: channels,
   launch day, the first 90 days, and the five metrics that decide it.

The one-line summary: **the app is ship-quality and the business is pre-product.
Measure accuracy before you sell anything, and do not price the scan.**

## Running the skills yourself

The full pack is available in this repo as slash commands:

```
/founder:validate-idea     /founder:mvp-scope          /founder:pitch-deck
/founder:product-brief     /founder:pricing-strategy   /founder:fundraise-prep
/founder:competitor-matrix /founder:go-to-market       /founder:metrics-dashboard
/founder:persona-gen       /founder:landing-page       /founder:email-sequence
/founder:user-interviews
```

`/founder:landing-page` and `/founder:metrics-dashboard` are the natural next
two — the go-to-market plan references copy and a dashboard that neither of
these documents produces.
